# Carbon Emission Model for HPC Workload Simulation

> Project: Energy and Carbon Monitoring in High Performance Computing (HPC) Systems
> Implementation: `slurm_simulator/workload-gen/analyze_run.py`
> Power parameters: `slurm_simulator/workload-gen/generate_workload.py`

---

## 1. Overview

The Slurm simulator does **not** execute real applications and has **no hardware power meters. Carbon emissions are estimated by combining three layers:

```
Carbon emissions  =  Activity data (simulator)  ×  Energy model (power × time)  ×  Grid carbon intensity
```

This follows the same pattern as operational HPC carbon accounting: real clusters use measured energy from RAPL/IPMI (`ConsumedEnergyRaw` in `sacct`); in simulation we **s synthesize** energy from a power model applied to resource occupancy times extracted from `slurmctld.log`.

---

## 2. Data Pipeline

### 2.1 Activity data (from `slurmctld.log`)

`analyze_run.py` parses the controller log for each `JobId`:

| Field | Log pattern | Purpose |
|---|---|---|
| Submit time | `_slurm_rpc_submit_batch_job: JobId=N` | Queue wait |
| Start time | `sched: Allocate JobId=N` or `_start_job: Started JobId=N` | Run start |
| End time | `_job_complete: JobId=N done` | Run end |
| State | `Time limit exhausted for JobId=N` | COMPLETED vs TIMEOUT |

**Runtime (hours):**

\[
t_{\mathrm{run}} = \frac{t_{\mathrm{end}} - t_{\mathrm{start}}}{3600\ \mathrm{s}}
\]

Energy and carbon are computed **only** when both start and end timestamps exist. Jobs that never started or never finished leave `energy_kwh` and `co2_kg` empty in `job_results.csv`.

### 2.2 Resource profile (from `workload_profile.csv`)

Generated by `generate_workload.py` for each job:

| Field | Meaning |
|---|---|
| `cores` | Allocated CPU cores (`-n` in `sim.events`) |
| `gpus` | Number of GPUs |
| `cpu_w_per_core` | CPU power per core (W/core) |
| `gpu_w` | GPU power per device (W) |

### 2.3 Global parameters (CLI overrides)

| Parameter | Default | Meaning |
|---|---|---|
| `PUE` | **1.2** | Total facility energy / IT equipment energy |
| `CI` | **150 gCO₂/kWh** | Grid carbon intensity (UK grid order of magnitude) |

```bash
python3 workload-gen/analyze_run.py --pue 1.2 --ci 150
```

## 3. Core Formulas

### Step 1 — IT power for one job (watts)

\[
P_{\mathrm{job}} = N_{\mathrm{cores}} \cdot w_{\mathrm{cpu}} + N_{\mathrm{gpu}} \cdot w_{\mathrm{gpu}}
\]

**Code:**

```python
power_w = cores * cpu_w_per_core + gpus * gpu_w
```

**Assumption:** Allocated cores and GPUs draw constant power at **100% utilisation** (TDP upper bound — conservative).

---

### Step 2 — IT energy (kWh)

\[
E_{\mathrm{IT,job}} = \frac{P_{\mathrm{job}} \cdot t_{\mathrm{run}}}{1000}
\]

(`power_w` in watts, `t_run` in hours; divide by 1000 for kWh.)

---

### Step 3 — Total facility energy including overhead (kWh)

\[
E_{\mathrm{job}} = E_{\mathrm{IT,job}} \times \mathrm{PUE}
= \frac{P_{\mathrm{job}} \cdot t_{\mathrm{run}}}{1000} \times \mathrm{PUE}
\]

**Code:**

```python
kwh = power_w * run_h / 1000.0 * args.pue
```

**PUE = 1.2** means: for every 1 kWh consumed by servers, the data centre draws ~1.2 kWh from the grid (cooling, power distribution, lighting, etc.).

---

### Step 4 — Carbon emissions (kg CO₂)

\[
\mathrm{CO2}_{\mathrm{job\ (kg)}} = \frac{E_{\mathrm{job}} \times \mathrm{CI}}{1000}
\]

`CI` is in **gCO₂/kWh**; dividing by 1000 converts to **kg CO₂**.

**Code:**

```python
co2_kg = kwh * args.ci / 1000.0
```

With default `CI = 150`: each kWh ≈ **0.15 kg CO₂**.

---

### Step 5 — Aggregation

\[
E_{\mathrm{total}} = \sum_{j \in \mathrm{finished}} E_j, \qquad
\mathrm{CO2}_{\mathrm{total}} = \sum_{j \in \mathrm{finished}} \mathrm{CO2}_j
= \frac{E_{\mathrm{total}} \times \mathrm{CI}}{1000}
\]

---

## 4. Compact Single-Job Equation

\[
\boxed{
\mathrm{CO2}_j\ \mathrm{[kg]}
= \frac{\mathrm{PUE} \cdot \mathrm{CI}}{10^{6}}
\cdot t_{\mathrm{run},j}\ \mathrm{[h]}
\cdot \Bigl( N_{\mathrm{cores},j}\, w_{\mathrm{cpu},j} + N_{\mathrm{gpu},j}\, w_{\mathrm{gpu},j} \Bigr)
\mathrm{[W]}
}
\]

Equivalent to the implementation in `analyze_run.py`.

## 5. Power Parameters

Defined in `generate_workload.py`:

### CPU (W per core)

| Partition class | \(w_{\mathrm{cpu}}\) | Basis |
|---|---|---|
| standard, bigmem, hugemem | **7.8 W/core** | Intel Xeon 8358: 250 W TDP ÷ 32 cores |
| gpu, gpu-h100, gpu-h100-nvl | **6.0 W/core** | Host CPU on GPU nodes (slightly lower weight) |

### GPU (W per device)

| GPU type | \(w_{\mathrm{gpu}}\) | Basis |
|---|---|---|
| NVIDIA A100 | **400 W** | TDP |
| NVIDIA H100 | **350 W** | TDP |
| NVIDIA H100-NVL | **400 W** | TDP |

Jobs without GPUs use \(N_{\mathrm{gpu}} = 0\).

## 6. Worked Examples

### Example A — AI training (Job 4 from `job_results.csv`)

- 96 cores, 8× A100, runtime 2.0 h
- \(w_{\mathrm{cpu}} = 6.0\), \(w_{\mathrm{gpu}} = 400\)

\[
P = 96 \times 6 + 8 \times 400 = 3776\ \mathrm{W}
\]

\[
E_{\mathrm{IT}} = \frac{3776 \times 2.0}{1000} = 7.552\ \mathrm{kWh}
\]

\[
E = 7.552 \times 1.2 = 9.06\ \mathrm{kWh}, \qquad
\mathrm{CO2} = \frac{9.06 \times 150}{1000} = 1.36\ \mathrm{kg}
\]

### Example B — MPI physics (Job 3)

- 512 cores, 0 GPU, standard partition, runtime 2.0 h
- \(w_{\mathrm{cpu}} = 7.8\)

\[
P = 512 \times 7.8 = 3993.6\ \mathrm{W}
\]

\[
E = \frac{3993.6 \times 2.0}{1000} \times 1.2 = 9.59\ \mathrm{kWh}, \qquad
\mathrm{CO2} = 1.44\ \mathrm{kg}
\]

### Example C — Small HTC job (Job 1)

- 4 cores, ~0.171 h runtime

\[
E \approx 0.01\ \mathrm{kWh}, \qquad \mathrm{CO2} \approx 0.001\ \mathrm{kg}
\]

### Example D — TIMEOUT without end time

If a job has a start time but no `_job_complete: done` in the log, `run_h` is undefined and **no energy or carbon row is produced** (see Job 12 in partial results).

## 7. Mapping to Real HPC and FastSim

| Stage | Real Stanage cluster | This project (simulation) |
|---|---|---|
| Occupancy duration | `sacct` Elapsed / Start / End | Parsed from `slurmctld.log` |
| Resources | AllocCPUS, GRES | `workload_profile.csv` |
| Energy | RAPL / IPMI → `ConsumedEnergyRaw` | \(P \times t \times \mathrm{PUE}\) |
| Carbon | Energy × time-varying grid CI | Energy × fixed CI = 150 g/kWh |

**FastSim** replays historical workloads and can use measured `ConsumedEnergyRaw`. Our approach is complementary: when no measured energy exists, the simulator provides **scheduling-faithful activity data** and the power model fills the energy gap.

---

## 8. Why Placeholder Jobs Can Be Replaced

The simulator never runs `pseudo.job`. The scheduler only sees:

- partition, node count, core count, GPU count
- requested walltime (`-t`) and simulated runtime (`-sim-walltime`)
- submit time (`-dt`)

If these follow realistic statistical distributions (log-normal runtimes, Poisson arrivals, power-of-two node counts, etc.), **queueing, backfill, and resource occupancy timelines are valid inputs** to the carbon model—even without real computation.

---

## 9. Assumptions and Limitations

1. **Constant 100% power** — No idle power, DVFS, or utilisation factor; TDP is typically an upper bound.
2. **Fixed PUE** — Real facility PUE varies; Stanage-specific values should replace 1.2 when available.
3. **Fixed carbon intensity** — UK grid CI varies hourly/seasonally; a constant 150 g/kWh is a simplification.
4. **IT equipment only** — Network, storage, and memory subsystem overhead beyond core/GPU TDP are not modelled separately.
5. **Simulated runtime** — Duration comes from `-sim-walltime`, not measured application performance.
6. **Partial runs** — Without `All done` in the log, totals include only jobs with both start and end timestamps (a **lower bound** on full-workload emissions).

Document partial-run results explicitly, e.g. *“Based on 71 of 140 jobs with complete scheduling records.”*

## 10. Extensions (Future Work)

**Utilisation correction:**

\[
P_{\mathrm{job}} = \eta_{\mathrm{cpu}}\, N_{\mathrm{cores}}\, w_{\mathrm{cpu}} + \eta_{\mathrm{gpu}}\, N_{\mathrm{gpu}}\, w_{\mathrm{gpu}}
\]

**Time-varying carbon intensity:**

\[
\mathrm{CO2}_{\mathrm{job}} = \int_{t_{\mathrm{start}}}^{t_{\mathrm{end}}} P_{\mathrm{job}}(t)\,\mathrm{PUE}\,\mathrm{CI}(t)\,dt
\]

Discretise into hourly slices with grid CI per interval.

**Per-node breakdown (MPI jobs):**

\[
P_{\mathrm{job}} = \sum_{\mathrm{nodes}} \bigl( n_{\mathrm{cores,node}}\, w_{\mathrm{cpu}} + n_{\mathrm{gpu,node}}\, w_{\mathrm{gpu}} \bigr)
\]

Equivalent to the current aggregate formula when total cores and GPUs are correct.

## 11. How to Reproduce

```bash
cd slurm_simulator

# Generate workload (optional; already present as sim.events.realistic)
python3 workload-gen/generate_workload.py --hours 12 --jobs 140 --seed 42

# Run simulation
./run-stanage.sh realistic

# Compute energy and carbon per job
python3 workload-gen/analyze_run.py --pue 1.2 --ci 150
```

**Output:** `stanage-sim/job_results.csv` — columns `energy_kwh`, `co2_kg`, plus submit/start/end and job class.

**Example partial-run summary:**

```
finished     : 71  (timeout: 31)
total energy : 70.8 kWh  (PUE=1.20)
total CO2    : 10.6 kg   (CI=150 gCO2/kWh)
```

Check: \( \mathrm{CO2} = 70.8 \times 150 / 1000 = 10.62\ \mathrm{kg} \).
